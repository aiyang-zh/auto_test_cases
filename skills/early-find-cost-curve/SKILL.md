# 早发现与缺陷成本曲线

## R — 核心原则 (Reading)

> 费用指数级地增长——也就是说，随着时间的推移，费用呈十倍地增长。……当早期编写产品说明书时发现并修复缺陷，费用只要1美元甚至更少。……如果是客户发现的，费用可能达到数千甚至数百万美元。

> 软件测试员的目标是尽可能早地找出软件缺陷，并确保其得以修复。……千万不要在无法达到的完美上纠缠和兜圈子。

---

## I — 方法论骨架 (Interpretation)

缺陷发现得越晚，处理费用往往不是线性涨，而是数量级上涨：说明书期 ≈ 零钱；编码/测试期贵一截；客户现场可能摧毁利润（支持、召回、诉讼）。

Crosby 框架：
- **一致性费用**：一次做对/测对的计划与执行投入
- **非一致性费用**：内外部失败（分离、返工、客户侧灾难）

“质量是免费的”= 一致性费用 + 内部失败，通常仍小于外部失败——不是口号。测试员目标三要素：找缺陷、尽早找、推动修复（修复也可是文档/培训/砍功能）。同时承认：并非所有缺陷都必须改代码；取舍是商业风险，但低估外部成本会翻车。

## A1 — 典型应用 (Past Application)

### 案例 1: 迪斯尼《狮子王》光盘配置灾难
- **问题**: 只在开发机验证，主流 PC 不能跑；大规模出货后支持崩溃。
- **做法**: 若说明书阶段界定目标配置，代价几乎可忽略；拖到客户则召回级费用。
- **结论**: 晚发现足以耗尽利润。
- **结果**: 投诉电话、召回、换盘与再一轮开发测试费用。

### 案例 2: 奔腾 FDIV——内部已知却判不修
- **问题**: 发布前已发现，管理层认为不常见、赶期限。
- **做法**: 显示“发现≠解决”；错误低估外部/声誉成本。
- **结论**: 风险取舍正当，但外部失败可远大于内部估算。
- **结果**: 道歉并花费逾 4 亿美元换片。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 争取测试前移或需求阶段介入的预算/排期
2. 解释为何“以后再说”的缺陷可能极贵
3. triage：修 / 不修 / 推迟时要纳入外部失败成本
4. 向非技术管理者讲“质量费用”故事

### 语言信号 (用户的话里出现这些就应激活)

- 「越晚修越贵 / 缺陷成本曲线」
- 「质量是免费的 / cost of quality」
- 「这 bug 能不能拖到下个版本 / 让客户先用着」
- 「为什么要在需求阶段就测」

### 与相邻 skill 的区分

- 与 `risk-based-test-selection` 的区别: 后者解决**测什么、测多少**；本 skill 解决**时间轴上的费用论证与修/不修的成本直觉**。
- 与 `professional-bug-reporting` 的区别: 写单说服力 vs 费用结构叙事；可组合但触发不同。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **定位缺陷/决策在生命周期的位置**
   - 完成标准: 标在说明书 / 设计 / 编码 / 测试 / 发布后哪一段。

2. **粗算两类费用**
   - 完成标准: 列出一致性投入（现在测/修）vs 内外部非一致性（返工、支持、召回、声誉）；用数量级而非伪精确数字。

3. **映射到行动**
   - 完成标准: 给出前移测试、现在修、带缓解发布、或明确接受风险中的建议；若建议不修，写明被低估的外部成本检查项。
   - 判停条件: 若问题其实是“选哪些用例”，转 `risk-based-test-selection`；若是“怎么写单”，转 `professional-bug-reporting`。

4. **拒绝完美主义死结**
   - 完成标准: 提醒目标是早找并推动恰当修复，不是证明零缺陷。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 需要压缩用例集、找最优测试量 → `risk-based-test-selection`
- 需要可再现步骤与严重性字段 → `professional-bug-reporting`
- 安全关键系统“绝不能按商业曲线停测”的合规场景——曲线是启发式，不是免责金牌

### 常见失败模式

- 只证实“能跑”而漏缺陷，浪费修复窗口
- 已知缺陷以进度压下，低估外部失败（奔腾）
- 配置覆盖极窄却大规模发货（狮子王）
- 短视技术债赌“系统会被替换”（Y2K）

### 适用边界与局限

- “十倍增长”是教学数量级模型，非每个组织的计量会计；现代需结合 MTTR、客户流失、SLO 违约金
- “质量免费”来自制造业大师，对软件需求漂移与不确定性的论证偏短
- 持续交付下“发布后”成本形态变为热修/功能开关，曲线仍成立但阶段标签要重映射

### 容易混淆的邻近方法论

- 技术债利息：相近经济直觉；本 skill 聚焦**缺陷发现时刻**
- 最优测试量曲线（测多费用升）：相关但问题是抽样停测，交给 risk-based skill
