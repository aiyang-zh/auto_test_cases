# 四象限测试技术选型

## R — 核心原则 (Reading)

> 测试基础已经讲述了三种技术：静态黑盒（测试产品说明书）、动态黑盒（测试软件）和静态白盒（检查程序代码）。接下来是第4个基本测试技术——动态白盒测试。在测试软件时，我们将利用X光眼镜洞察软件的“盒子”里面。

---

## I — 方法论骨架 (Interpretation)

用两个轴切分测试技术：是否运行产品（静态 vs 动态）× 是否利用实现信息（黑盒 vs 白盒）。

|  | 黑盒（不知/不依赖实现） | 白盒（可读代码/结构） |
|---|---|---|
| **静态** | 审查说明书/需求文档 | 审查设计与代码（不执行） |
| **动态** | 戴“眼罩”跑行为与数据 | 戴“X 光”边跑边用结构信息 |

选型先问三件事：有无说明书？有无代码访问权？当前能否运行？再选象限，最后在象限内叠专项技法（等价类、覆盖、审查清单等）。

白盒能删冗余、打内部边界，但易对实现产生偏见；黑盒保持用户视角。四象限互补，不是互斥教派。

---

## A1 — 典型应用 (Past Application)

### 案例 1: 二手车类比
- **问题**: 如何直觉区分静/动？
- **做法**: 踢轮胎/看引擎=静态；发动上路=动态；黑白盒比作是否打开理解内部。
- **结论**: 静态黑盒=测说明书；动态黑盒=不知实现地跑软件。
- **结果**: 建立技术地图的入口语言。

### 案例 2: 动态白盒 atoi / 覆盖
- **问题**: 有代码访问权时如何测模块？
- **做法**: 先按说明书建黑盒用例再看代码增减；用驱动/桩与覆盖观察中间状态与路径。
- **结论**: 白盒信息用于决定测什么/不测什么，目标仍是找缺陷而非调试修复。
- **结果**: 补齐第四象限，并警告先白盒易“按实现测实现”。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 新人问黑盒白盒区别、不知从哪类活动开始。
2. 只有安装包/无源码/无完整说明书，不知还能做什么。
3. 有代码评审机会，纠结该静态看代码还是先跑起来。
4. 团队把“测试”默认等同于点点点的动态黑盒，忽略说明书与代码审查。

### 语言信号 (用户的话里出现这些就应激活)

- "黑盒还是白盒 / static or dynamic"
- "四象限 / black-box white-box"
- "没有说明书怎么测 / 只有二进制"
- "要不要做代码审查还是直接跑"

### 与相邻 skill 的区分

- 与 `equivalence-and-boundaries` 的区别: 彼 skill 是动态黑盒（及次边界思维）内的抽样技法；本 skill 先选象限。
- 与 `risk-based-test-selection` 的区别: 风险决定力度与停测；本 skill 决定技术族类。
- 与 `prove-presence-not-absence` 的区别: 认识论 vs 技术选型矩阵。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **收集约束**
   - 有无说明书/PRD？有无源码？能否运行？时间盒？
   - 完成标准: 三问都有是/否/部分答案。

2. **映射到象限**
   - 有文档 → 静态黑盒优先；能跑且无码 → 动态黑盒；有码不跑 → 静态白盒；有码且跑 → 动态白盒可叠加。
   - 完成标准: 写下主象限 + 可选辅象限。

3. **给出该象限的下一步动作**
   - 静态黑盒→文档高空/低空审查；动态黑盒→等价类与边界；静态白盒→审查清单；动态白盒→先黑盒用例再覆盖/驱动。
   - 完成标准: 用户拿到可执行的下一小时任务，而非术语课。
   - 判停条件: 若主象限已是动态黑盒且问的是取点，转 `equivalence-and-boundaries`。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用户已知道要用动态黑盒，只要字段测试数据。
- 用户在争论放行话术能否说“无缺陷”。
- 把四象限当成现代测试策略全家桶（未覆盖契约测、混沌、可观测性等）。

### 常见失败模式

- 白盒测试易形成偏见，无法客观。
- 只做确认（对照说明书）不做验证（对照用户需求）——哈勃镜。
- 动态白盒与调试目标混淆（找缺陷 vs 修缺陷）。

### 适用边界与局限

- 四象限叙事贴合桌面/早期 Web 与“说明书 + 源码 + 本地运行”假设；云原生、API-only、配置即代码等场景需把“说明书/代码”外延到 OpenAPI、IaC、特性开关配置。
- 安全与网站相关选型偏入门，选型后仍需当代威胁模型补丁。

### 容易混淆的邻近方法论

- 探索测试（无说明书时把软件当活说明书）——可视为动态黑盒的适应模式。
- 单元/集成/系统分层——正交维度，可与四象限交叉。
