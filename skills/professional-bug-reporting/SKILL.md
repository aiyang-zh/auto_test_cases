# 专业缺陷报告

## R — 核心原则 (Reading)

> 这些原则——尽快报告软件缺陷、有效描述它们、在报告中不掺杂评论以及对报告跟踪到底——都应该成为常事。……如果希望卓有成效地报告软件缺陷，并使其得以修复，这些就是要遵循的基本原则。

> 严重性表示软件缺陷的恶劣程度……优先级表示修复缺陷的重要程度和紧迫程度。

---

## I — 方法论骨架 (Interpretation)

找到缺陷只做了一半；**报告质量决定它会不会被修**。四原则：快、有效描述、中立、跟踪到底。

有效描述四要素：短小、单一、明显通用、可再现。有疑问就拆成多张单，宁可多报也不要堆症状导致漏修。能分离就分离——把“自动化跑 6 小时”收成“10 个常用按键”。

严重性（碰了有多坏）与优先级（多急着修）正交打分，服务 triage，不是情绪标签。报告针对产品不针对人；从打开盯到关闭，必要时用更通用用例重开“不修”决策。

---

## A1 — 典型应用 (Past Application)

### 案例 1: 自动化 6 小时 vs 10 个神奇按键
- **问题**: 长跑日志当报告，经理以为是极端乱敲才出现，倾向不修。
- **做法**: 分离缺陷，收缩为明显、通用、可再现的最小步骤再报告。
- **结论**: 报告形态改变修复决策。
- **结果**: 缩成常用按键后更可能获得应有重视。

### 案例 2: “不修”被更通用用例推翻
- **问题**: 程序员与经理判不修。
- **做法**: 测试员补充更明显通用的失败用例，重开并跟踪。
- **结论**: 优秀测试员监视修复全过程，用证据说服而非对立指责。
- **结果**: 项目经理同意并指定修复。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 写 bug 单、改写模糊报告
2. 缺陷被标 won't fix，需要加证据争取修复
3. 混淆严重性与优先级如何打
4. 偶现/长步骤缺陷需要分离与再现

### 语言信号 (用户的话里出现这些就应激活)

- 「帮我写个 bug / 缺陷报告」
- 「怎么写才会被修」「可再现步骤」
- 「严重性怎么定 / severity priority」
- 「缺陷分离 / isolate the bug」

### 与相邻 skill 的区分

- 与 `risk-based-test-selection` 的区别: 后者决定**测什么/停何处**；本 skill 决定**怎么把已发现问题说清楚并推修复**。
- 与 `early-find-cost-curve` 的区别: 费用曲线论证**为何早修值得**；本 skill 是报告与 triage 沟通术。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **澄清症状与是否可拆分**
   - 完成标准: 每个报告只盯一个症状；存疑则拆多单。

2. **分离到最小可再现步骤**
   - 完成标准: 步骤短小、明显、通用、他人可复现；去掉无关长跑/噪声。
   - 判停条件: 若无法稳定复现，先输出分离尝试清单（时序、状态、资源、硬件），暂缓正式定级结论。

3. **中立撰写 + 正交定级**
   - 完成标准: 只陈述事实；给出严重性与优先级及理由；无人身评价。

4. **跟踪与必要时重开**
   - 完成标准: 写明期望状态流转与复验标准；若被不修，列出可补充的更通用证据类型。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 还在决定测哪些类/何时停测 → `risk-based-test-selection`
- 管理沟通只要费用曲线/“质量免费”叙事 → `early-find-cost-curve`
- 纯查询某工具字段怎么填且无方法论问题——给模板即可，不必全流程激活

### 常见失败模式

- 报告掺杂评论、针对个人，引发对立
- 多缺陷堆一张单，只修第一个其余被忘
- 找到重要缺陷却跟丢；或用极端路径描述导致被低估
- 已知缺陷以“不常见”压下不修且沟通失当（奔腾启示：报告与对外口径都重要）

### 适用边界与局限

- 样例偏桌面手工/早期缺陷库 UI；Jira/线性工作流字段名不同但原则不变
- 对异步分布式偶现、生产可观测性取证着墨少，需补日志/trace 证据链
- 开源社区 issue 礼仪与安全漏洞负责任披露流程超出本 skill 常见范围

### 容易混淆的邻近方法论

- 根因分析 / 5 Whys：找病因；本 skill 先报告**症状**并保证可修决策
- 事件管理（incident）：生产应急沟通；可借用中立与影响描述，但流程不同
